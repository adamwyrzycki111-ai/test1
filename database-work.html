Schema Design for SaaS Systems

Multi-tenant database patterns that balance performance, isolation, and maintainability.

B2B SaaS Multi-Tenant Architecture

Design Approach

  • Soft-deletion with organization_id foreign keys
  • Tenant-scoped queries via middleware
  • Row-level security patterns for sensitive data
  • Archive strategy for inactive tenants

Outcome

  • Single database supports 500+ tenants without contention
  • Query isolation prevents cross-tenant data leaks
  • Tenant migration time: under 2 seconds average

E-commerce Catalog Schema

Design Approach

  • Normalized product attributes (EAV pattern avoided)
  • Variant matrix with proper indexing
  • Inventory partitioned by warehouse location
  • Price history with effective date ranges

Outcome

  • Product listing queries: under 50ms
  • Supports 100k+ SKUs without performance degradation
  • Price rollback capability within 1 second

Query Optimization

Real performance improvements from production systems.

Dashboard Analytics Query

Before: 3.8s → After: 420ms

Problem

N+1 queries loading aggregated metrics. Dashboard loaded 200+ separate queries for a single view.

Solution

  • Consolidated to single query with indexed aggregations
  • Materialized view for real-time metrics
  • Redis caching layer with 5-minute TTL

Search with Filters

Before: 2.1s → After: 85ms

Problem

Full table scan with PHP-side filtering. 50k records processed in memory for every search request.

Solution

  • Composite indexes on filterable columns
  • Query scope pushed to database level
  • Pagination added to prevent offset performance issues

User Activity Feed

Before: 1.4s → After: 95ms

Problem

Polymorphic relationships causing implicit joins. Feed generation touched 6 tables per item.

Solution

  • Denormalized activity feed table with queue-based updates
  • Single table query with cursor-based pagination
  • Background job for feed recalculation on user action

Composite Indexes for Common Queries

Approach

Average query time reduced 65%

Large-Scale Migrations

Production-safe migration strategies for high-stakes systems.

Billing System Migration

Zero Downtime

Scope

  • Migrated payment processing from legacy system
  • 2M+ transaction records
  • Stripe and PayPal dual integration

Strategy

  • Dual-write period with reconciliation jobs
  • Shadow table migration pattern
  • Backfill with batch processing and rate limiting
  • Rollback capability via feature flag

Result

  • Zero downtime deployment
  • Data consistency verified across both systems
  • Migration completed over single weekend

User System Consolidation

Zero Downtime

Scope

  • Merged three legacy user tables into single schema
  • 1.5M users with complex permission relationships
  • 4 external integrations dependent on user IDs

Strategy

  • UUID mapping layer for external references
  • Incremental migration with automatic retries
  • Read replica for validation before cutover

Result

  • External integrations unaffected
  • Zero failed logins during migration
  • Query performance improved by 40%
